Целевая форма — **карта компетенций с минимумом текста**. Эссе и пересказ теории намеренно вынесены за пределы основного маршрута: они либо ужаты до коротких определений, либо заменены ссылками на первоисточники в материалах листьев.

## Из чего состоит сайт

- Верхнеуровневая mermaid-схема ветвей — в [`README.md`](https://github.com/jtprogru/The-Way-of-SRE/blob/main/README.md) на GitHub.
- Интерактивный паук (главная страница) и branch-views — рендерятся на сайте из `src/data/roadmap.ts`.
- Содержимое каждого листа — на сайте по адресу `/The-Way-of-SRE/leaves/<branch>/<slug>/`; исходники в `src/content/docs/leaves/<branch>/<slug>.md`.
- Шаблон листа — [`src/content/docs/leaves/_template.md`](https://github.com/jtprogru/The-Way-of-SRE/blob/main/src/content/docs/leaves/_template.md) в репозитории.

## Структура листа

Каждый лист идёт по единому шаблону:

1. **Lead-параграф** (1–2 предложения) — граница концепта, чем отличается от соседних листьев.
2. **`:::note[Метаданные листа]`** — ветвь, путь в графе, SFIA-уровни, приоритет, статус.
3. **Что должен уметь** — формулировки уровня «умеет N», привязанные к диапазону SFIA-уровней.
4. **Материалы** — внешние источники, отсортированные по форматам (книги / статьи / курсы / инструменты). Сюда же стекает конкретный тулинг, который запрещён в графе политикой детализации.
5. **Best practices** — правило + антипаттерн + обоснование «почему», в каждом пункте.
6. **Связанные листья** — с типом связи (предпосылка / продолжение / альтернатива).
7. **Открытые вопросы** — опционально, для листьев в статусе `draft`.

Подробные правила заполнения шаблона — в файле [`src/content/docs/leaves/_template.md`](https://github.com/jtprogru/The-Way-of-SRE/blob/main/src/content/docs/leaves/_template.md). Astro игнорирует `_`-префиксированные файлы, поэтому шаблон не публикуется как страница, но виден в GitHub UI.

## Источники структуры

| Файл | За что отвечает |
| ---- | --------------- |
| `src/data/roadmap.ts` | L1-узлы каждой ветви, **priorities L1**, leaves под L1 |
| `src/content/docs/sre-{culture,engineering,practices}.mdx` | L1 + L2 inventory концептов (как nested list под каждым L1) |
| `src/content/docs/leaves/<branch>/<slug>.md` | Содержимое одного листа |
| `inventory/overlaps.md` *(GitHub)* | Решения по пересечениям между ветвями (рабочий артефакт) |

Подробнее про инварианты — в [Методологии](/The-Way-of-SRE/methodology/#источники-структуры).

## Как контрибутить

- **Поправки в листьях** — PR с одним атомарным изменением в одном файле.
- **Изменения в структуре графа** (L1 в `src/data/roadmap.ts` и L2 inventory в `sre-*.mdx`) — обязательно сверка с [Методологией](/The-Way-of-SRE/methodology/) и `inventory/overlaps.md` в репозитории.
- **Новые листья** — создаются строго по шаблону `src/content/docs/leaves/_template.md` в `src/content/docs/leaves/<branch>/<slug>.md`, с обновлением навигации (`astro.config.mjs` + `src/data/roadmap.ts`).
- **Обсуждение** — [Чат в Telegram](https://t.me/jtprogru_chat), новые листья и анонсы — в [Канале](https://t.me/jtprogru_channel).
