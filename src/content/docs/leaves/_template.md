## Что должен уметь

Формулировки уровня «умеет N» — конкретные, проверяемые действия и артефакты. Каждый пункт привязан к диапазону уровней SFIA, где он становится требованием.

- **L3** — <умение начального уровня>
- **L4** — <умение среднего уровня>
- **L5** — <умение опытного инженера>
- **L6+** — <умение, ожидаемое от senior/staff/principal>

Формат пункта: глагол действия + объект + критерий проверки.

> Хорошо: «Умеет записать SLI как отношение good events / valid events и обосновать выбор знаменателя».
>
> Плохо: «Понимает SLI» — нет критерия проверки.

## Правила заполнения шаблона

Этот блок **удаляется** из реальных листьев. Здесь — для тех, кто заполняет шаблон впервые.

- **Где живёт лист.** Реальные листья создаются в `src/content/docs/leaves/<branch>/<slug>.md` в корне репозитория. Этот шаблон — `src/content/docs/leaves/_template.md` — образец, который Astro игнорирует (префикс `_`), но GitHub UI показывает.
- **Slug = `<имя-в-нижнем-регистре-через-дефис>`.** Совпадает с URL на сайте (`/leaves/<branch>/<slug>/`) и с `href` в `src/data/roadmap.ts`.
- **Метаданные через `:::note` callout, а не во фронт-маттере.** Starlight ожидает `title`/`description`/`sidebar` во фронт-маттере, а свободные поля (ветвь, путь, SFIA, приоритет, статус) живут в визуальном callout под фронт-маттером.
- **`sfia_levels` и `priority` — независимые измерения.** Не смешивайте «обязательность для роли» (priority) с «уровнем зрелости инженера» (sfia_levels). Это разные оси.
- **«Что должен уметь» — это критерии оценки, а не описание области.** Если пункт нельзя проверить на конкретном кандидате или в конкретной системе, он переформулируется или удаляется.
- **Материалы — курируемый список, а не reading list.** Каждая ссылка отвечает на вопрос «кому конкретно это пригодится и для чего». Если ответа нет — ссылка не добавляется.
- **Best practices без обоснования «почему» — не best practices.** Без причины правило не пройдёт ревью PR.
- **Тулинг живёт здесь, а не в графе.** См. [Методологию](/The-Way-of-SRE/methodology/), раздел «Что не попадает в граф».
- **Связанные листья — реальные ссылки или `(TBD)`.** Если соседний лист уже есть на сайте — `**[Имя](/The-Way-of-SRE/leaves/<branch>/<slug>/)**`. Если ещё нет — `**Имя** *(TBD)*`. Не оставляйте «битых» URL.
- **`status`** проходит путь `draft → review → stable`. В `stable` лист переводится только после ревью PR. Текущее значение можно держать в строке «Статус» callout-блока метаданных.
- **После создания листа — обновить навигацию.** Добавить узел в `astro.config.mjs` (sidebar) и `href` в соответствующей записи `src/data/roadmap.ts`.
