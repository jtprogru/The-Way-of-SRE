## Правила заполнения шаблона

Этот блок **удаляется** из реальных листьев. Здесь — для тех, кто заполняет шаблон впервые.

### Структурные правила

- **Где живёт лист.** Реальные листья создаются в `src/content/docs/leaves/<branch>/<slug>.md` в корне репозитория. Этот шаблон — `src/content/docs/leaves/_template.md` — образец, который Astro игнорирует (префикс `_`), но GitHub UI показывает.
- **Slug = `<имя-в-нижнем-регистре-через-дефис>`.** Совпадает с URL на сайте (`/leaves/<branch>/<slug>/`) и с `href` в `src/data/roadmap.ts`.
- **Метаданные через `:::note` callout, а не во фронт-маттере.** Starlight ожидает `title`/`description`/`sidebar` во фронт-маттере, а свободные поля (ветвь, путь, SFIA, приоритет, статус) живут в визуальном callout.
- **`sfia_levels` и `priority` — независимые измерения.** Не смешивайте «обязательность для роли» (priority) с «уровнем зрелости инженера» (sfia_levels).
- **«Что должен уметь» — это критерии оценки, а не описание области.** Если пункт нельзя проверить — переформулировать или удалить.
- **Материалы — курируемый список с авторской оценкой**, а не reading list.
- **Связанные листья — реальные ссылки или `(TBD)`.** Не оставляйте битых URL.
- **После создания листа — обновить навигацию.** Добавить узел в `astro.config.mjs` (sidebar) и `href` в `src/data/roadmap.ts`.

### Правила голоса и стиля

Полные правила — в [`inventory/style-guide.md`](https://github.com/jtprogru/The-Way-of-SRE/blob/main/inventory/style-guide.md) и [`inventory/terminology.md`](https://github.com/jtprogru/The-Way-of-SRE/blob/main/inventory/terminology.md). Краткая выжимка для контрибутора:

- **От первого лица.** «Я», «я регулярно вижу», «по моим наблюдениям», не «команды должны».
- **Мнение через наблюдение, не через категоричный выбор.** «Я вижу, что чаще выбирают X» вместо «я бы выбрал X».
- **Минимум по одному из каждого:** конкретный пример (публичный incident или наблюдение), явное мнение автора, граница применимости.
- **Description ≤ 200 символов**, не пересказ листа.
- **Lead не дублирует description.**
- **Best practices ≤ 50% в шаблоне «утверждение/антипаттерн/правильно»**; остальное прозой.
- **Терминология:** устоявшиеся англицизмы (SRE, SLI/SLO, postmortem, runbook, on-call, blameless) — курсивом без склонения. Явные кальки (`decision log`, `shift transition`, `sitrep cadence`) — переводим. Запрещены гибриды через дефис («blameless-принцип», «high-severity incident», «pull-based модель»).
- **`status`** проходит путь `draft → review → stable`.
