## Правила заполнения шаблона

Этот блок **удаляется** из реальных листьев. Здесь — для тех, кто заполняет шаблон впервые.

- **Фронт-маттер обязателен.** Поля `name`, `branch`, `path`, `sfia_levels`, `priority`, `status` — без них лист не считается завершённым.
- **`sfia_levels` и `priority` — независимые измерения.** Не смешивайте «обязательность для роли» (priority) с «уровнем зрелости инженера» (sfia_levels). Это разные оси.
- **«Что должен уметь» — это критерии оценки, а не описание области.** Если пункт нельзя проверить на конкретном кандидате или в конкретной системе, он переформулируется или удаляется.
- **Материалы — курируемый список, а не reading list.** Каждая ссылка отвечает на вопрос «кому конкретно это пригодится и для чего». Если ответа нет — ссылка не добавляется.
- **Best practices без обоснования «почему» — не best practices.** Без причины правило не пройдёт ревью PR.
- **Тулинг живёт здесь, а не в графе.** См. [`methodology.md`](../methodology.md), раздел «Что не попадает в граф».
- **`status`** проходит путь `draft -> review -> stable`. В `stable` лист может быть переведён только после ревью PR.
