# Терминология: что переводим, что оставляем

Рабочий документ. Решает один вопрос: **когда в тексте употребляется английский термин, а когда — русский перевод**. Создан в ответ на критику: «для большинства терминов есть русифицированные и понятные названия».

Парный документ: `style-guide.md` (про голос и структуру). Этот — про слова.

---

## Принципы

1. **Цель — читаемость, а не борьба с англицизмами.** Если перевод хуже читается или вообще не используется в русскоязычной SRE-индустрии — оставляем латиницу.
2. **Двуязычная мешанина без правила хуже любого из крайних вариантов.** Сейчас в одном абзаце соседствуют «sitrep cadence», «decision log», «role rotation», «mitigation phase», «handoff sync». Это не русский и не английский — гибрид, который раздражает обе аудитории.
3. **Контекст важнее категории.** Один и тот же термин в техническом разделе и в культурном может писаться по-разному. Например, *runbook* в инженерном листе — латиницей, в культурном про onboarding — допустим «рантбук» или «инструкция по обработке инцидента» (в зависимости от смысла в предложении).
4. **Графика англицизмов — единая.** Если оставляем латиницу — пишем латиницей **курсивом, без склонения**. Не «онколу», не «по pull-у», не «через pipeline-ы». См. секцию «Графика» ниже.

---

## Категория A — оставляем латиницей

Термины, которые в русскоязычной SRE-индустрии **устойчиво** используются на английском. Перевод их выглядит странно и затрудняет поиск по тексту.

### Профессиональная лексика SRE

- *SRE, SLI, SLO, SLA, error budget, burn rate*
- *postmortem, runbook, on-call, on-call rotation, paging, pager*
- *blameless, just culture*
- *toil, observability, telemetry, alerting*
- *severity* (`SEV0` / `SEV1` / `SEV2`)
- *Incident Commander (IC)* — допустим перевод «руководитель инцидента» при первом упоминании, далее IC

### Инженерные термины

- *CI/CD, IaC, GitOps, Kubernetes, Helm, Kustomize, Argo CD, Flux*
- *manifest, controller, sidecar, operator, CRD*
- *canary, blue-green, A/B, feature flag, progressive delivery*
- *rollback, hotfix, deploy* (но «релиз» — по-русски, устоялся)
- *throughput, latency, percentile* (`p50`, `p95`, `p99`)
- *RBAC, IAM, SSO, MFA*

### Security-лексика

- *STRIDE, PASTA, OCTAVE, LINDDUN, VAST* (имена фреймворков)
- *MITRE ATT&CK, OWASP*
- *CVE, SBOM, SLSA, SAST, DAST, IAST*
- *zero-trust*

### Имена собственные и тулзы

- Все названия инструментов — латиницей: *Prometheus, Grafana, Sloth, Nobl9, PagerDuty, Sentry, Datadog, OpenTelemetry, Jaeger, Tempo, Loki, Argo Rollouts, Flagger*.
- Имена компаний — латиницей: *Google, Stripe, Cloudflare, GitHub, GitLab*.

## Категория B — переводим однозначно

Термины, для которых русский перевод **уже используется** в русскоязычной литературе и доку, либо очевидная калька, режущая слух.

| Английский | Русский (наш выбор) | Комментарий |
|---|---|---|
| decision log | журнал решений | Прижилось в управленческой литературе |
| shift transition | передача смены | Стандарт |
| handoff | передача (контекста) | Подбираем по контексту: «передача дежурства», «передача инцидента» |
| role rotation | ротация ролей | Прямой перевод, читается нормально |
| audit trail | журнал аудита / след аудита | По контексту |
| sitrep cadence | ритм сводок / частота сводок | «Сводка» — устоявшийся военный/operational термин на русском |
| consensus seeking | поиск согласия | «Консенсус» допустим, но «согласие» точнее |
| tunnel vision | туннельное видение | Прижилось в русской психологии |
| living document | живой документ | Стандартная калька, но уже устоявшаяся |
| source of truth | источник истины | Устоявшаяся калька, нормальная |
| single source of truth | единый источник истины | То же |
| desired state | желаемое состояние | Стандарт в k8s-документации на русском |
| actual state | фактическое состояние | То же |
| self-heal | самовосстановление | Стандарт |
| drift | дрейф (конфигурации) | Прижилось |
| drift detection | обнаружение дрейфа | Стандарт |
| false positive | ложное срабатывание | Стандарт во всей IT-индустрии |
| false negative | ложный пропуск / необнаружение | По контексту |
| alert fatigue | усталость от алертов / алерт-усталость | По контексту |
| attack vector | вектор атаки | Стандарт в security-литературе |
| attack tree | дерево атак | Стандарт |
| attack surface | поверхность атаки | Стандарт в security-литературе |
| kill chain | цепочка атаки / kill chain | Допустима двойная форма |
| trust boundary | граница доверия | Стандарт |
| least privilege | (принцип) наименьших привилегий | Устоявшийся перевод в security-литературе |

| high-severity incident | критический инцидент / инцидент высокой степени | Не «high-severity incident». Если нужна точность — `SEV0` / `SEV1` |

## Категория C — двойная форма при первом упоминании

Термины, где русский перевод существует, но он **не самодостаточен**: читатель ищет связь с английской литературой. Решение — при первом упоминании в листе писать русский + латиницу в скобках, далее — что удобнее по контексту.

| Английский | Русский (первое упоминание) | Дальше |
|---|---|---|
| threat model | модель угроз (threat model) | модель угроз |
| threat modeling | моделирование угроз (threat modeling) | моделирование угроз |
| contributing factors | факторы вклада (contributing factors) | факторы вклада |
| root cause | корневая причина (root cause) | корневая причина — но осторожно, в листе про постмортем мы возражаем против самого термина |
| hindsight bias | взгляд задним числом (hindsight bias) | взгляд задним числом |
| counterfactual | контрфактическое рассуждение (counterfactual) | контрфакт |
| timeline | хронология (timeline) | таймлайн или хронология — по контексту |
| action items | задачи (action items) | задачи |
| follow-up | отслеживание / закрытие задач (follow-up) | follow-up или отслеживание |
| mitigation | гашение / митигация (mitigation) | По контексту: «гашение» для incident response, «митигация» для security |
| escalation | эскалация (escalation) | эскалация — уже почти не требует пояснения |
| war room | оперативный штаб (war room) | war room — уже устоявшееся |
| sitrep | сводка обстановки (sitrep) | сводка — но в категории B мы уже перевели «sitrep cadence» |
| scribe | секретарь / scribe | scribe в IC-роли — нередко оставляют латиницей как название роли |
| tabletop exercise | штабная игра (tabletop exercise) | штабная игра |
| game day | учения (game day) | game day — устоялось |
| service ownership | владение сервисом (service ownership) | владение сервисом |
| career ladder | карьерная лестница (career ladder) | карьерная лестница |

## Категория D — спорные, обсуждаем по контексту

Термины, где **нет хорошего перевода**, или перевод сильно меняет смысл. Здесь приму решение на пилоте (Фаза 2) и зафиксирую.

| Английский | Кандидаты на перевод | Проблема |
|---|---|---|
| pull-based / push-based | «модель pull / push» / «вытягивающий / толкающий подход» | Прямой перевод звучит дико, нужна формулировка через подлежащее («система сама подтягивает изменения», а не «pull-based система») |
| threshold-based alert | пороговый алерт | Перевод неплох, но в техническом контексте «threshold-based» читается чище. Решу на пилоте Engineering-листа |
| multi-window multi-burn-rate | многооконный многоскоростной алерт | По-русски — громоздко. Скорее всего оставлю как термин латиницей |
| dashboard | дашборд / панель | «Дашборд» уже устоялся в русском IT. Думаю, оставлю транслитерацию |
| pipeline (CI/CD) | конвейер / пайплайн | «Пайплайн» устоялся, «конвейер» используется реже |
| pipeline (data) | конвейер | В data-контексте «конвейер» читается лучше |
| stakeholder | заинтересованная сторона / стейкхолдер | «Заинтересованная сторона» — точно, но громоздко. Используется по контексту |
| ownership (вне service ownership) | владение / ответственность / зона ответственности | По контексту |
| accountability | подотчётность / ответственность | По контексту, оба варианта используются |
| escalation path | путь эскалации / схема эскалации | По контексту |
| outage | сбой / простой | По контексту: «outage» допустим в SRE-литературе, «сбой» — более общий |
| postmortem (как процесс vs документ) | постмортем (документ) / разбор инцидента (процесс) | Постмортем как документ оставляем; «провести постмортем» в значении ритуала — допустим перевод «провести разбор» |

Лист пополняется по ходу аудита и пилота.

## Графика англицизмов

Если оставляем английский термин (категория A или нерешённый D):

1. **Курсив** — при первом упоминании в листе, чтобы читатель видел: это термин-заимствование. Дальше можно без курсива, если термин уже встретился.
   - Пример: «Я записываю каждый *runbook* по единому шаблону. Хороший runbook начинается с симптома, а не с команды».
2. **Без склонения** — англицизмы латиницей не склоняем. Не «онколу», «пайплайну», «через runbookи». Если без склонения предложение разваливается — перестроить предложение.
   - Плохо: «Мы добавили в runbookи новые алерты».
   - Хорошо: «Мы добавили новые алерты в runbook'и каждой команды» (через апостроф) — допустимо.
   - Лучше: «В каждый runbook мы добавили новые алерты».
3. **С большой буквы — только собственные имена** (Prometheus, Argo CD, Google). Названия концепций — со строчной (sli, slo, runbook), кроме случаев, когда термин — аббревиатура (`SLI`, `SLO`).
4. **Аббревиатуры** (`SLI`, `SLO`, `IAM`, `RBAC`, `CVE`) — заглавными, моноширинно (`code`) при первом упоминании, дальше — обычным шрифтом.

## Графика составных конструкций

Запрещены гибриды через дефис:

- ❌ «blameless-принцип», «mitigation-фазы», «pull-based модель», «threshold-based алерт», «high-severity incident».
- ✅ либо «принцип *blameless*», «фазы гашения», «модель pull», «пороговый алерт», «инцидент высокой критичности» / `SEV0`.

Запрещены смешанные суффиксы:

- ❌ «дашборд'а», «pipeline'е», «runbook'у».
- ✅ «дашборда» (если транслитерируем), «в pipeline», «к runbook» (если оставляем латиницу, перестраиваем предложение).

## Применение

1. **При переписывании листа** (Фаза 3) — пройти по всем терминам, сверить с категорией. Категория B — перевести; категория C — добавить англ. в скобках при первом упоминании; категория A — оставить латиницей курсивом.
2. **При написании нового листа** — те же правила. В первом черновике допустимо нарушать (для скорости), но перед PR — отдельный проход по терминам.
3. **При сомнении** — добавить термин в категорию D и решить позже. Не «придумать перевод на коленке».

## Что в этом документе НЕ зафиксировано

- **Полный словарь** — это рабочий список, он покрывает термины, которые встретились в первых четырёх просмотренных листах. По ходу аудита (Фаза 1) и переписывания (Фаза 3) — расширяется.
- **Правила перевода названий доменов и подразделов** (Culture / Engineering / Practices, Observability, Configuration Management, Incident Management, Information Security) — это отдельный вопрос, решается на пилоте `format.mdx` / `methodology.mdx`. Сейчас живут на английском, и это, возможно, нормально, но требует осознанного решения.
- **Решение о переименовании листьев** (`title` в frontmatter) — отдельный вопрос. Сейчас названия листьев на английском (`SLI-based Alerting`, `War Room Patterns`). Переименование может ломать ссылки. Решаем после пилота.
