# Шаблон: Ежемесячный SRE Review

Ежемесячный SRE Review — встреча, на которой команда раз в месяц проходит по всем операционным практикам сразу: SLO, инциденты, алерты, runbook, toil, мощности, резервные копии, дежурства. Шаблон служит ей повесткой и протоколом. Часть про SLO и бюджет ошибок разобрана в листе [SLO / Budget Review](https://jtprogru.github.io/The-Way-of-SRE/culture/slo-budget-review/): там же сказано главное про любое ревью — оно проверяется тем, изменилось ли после него что-нибудь в плане.

## Когда применять

- Практик у команды уже несколько, и каждая живёт сама по себе: нет места, где видно всё сразу.
- Action items из постмортемов, аудит алертов и обновление runbook откладываются, потому что у них нет своего срока.
- Нужен регулярный срез для продукта или руководства, собранный из фактов.

## Когда не применять

- Вместо частого ревью SLO. Для бюджета ошибок месяц слишком редко, короткое ревью раз в неделю остаётся, и этот обзор его не заменяет.
- Обзор нужен как отчёт, а решений по нему принимать не будут. Встреча без решений умирает за пару месяцев.
- Нужна оценка зрелости практик по уровням. Это другой документ с другим ритмом.

## Как заполнять

- Текст в квадратных скобках — подсказка. Его нужно заменить своим или удалить.
- Числа собираются до встречи. На встрече обсуждают решения, а не читают дашборды.
- Обзор открывается решениями прошлого месяца: что сделано, что нет и что с этим делать.
- Разделы про практики, которых у команды нет, удаляются. Пустой раздел превращает обзор в формальность.
- Данные берутся из готовых документов: [toil log](toil-log.md), [постмортемы](incident-postmortem.md), [SLO-документы](slo-doc.md), [политика бюджета ошибок](error-budget-policy.md).
- У каждого решения есть владелец и срок. Если решение требует времени, записано, что ради него уходит из плана.

Сам документ начинается ниже линии. Копировать нужно только его.
