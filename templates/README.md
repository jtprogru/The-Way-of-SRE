# Шаблоны

Заготовки документов, которые появляются в работе SRE: от описания SLO до плана восстановления. Каждый шаблон — отдельный markdown-файл в этом каталоге.

Перечень с описаниями лежит на странице [Шаблоны](https://jtprogru.github.io/The-Way-of-SRE/templates/) сайта. Там же у каждого шаблона названы листья карты, где документ разобран: зачем он нужен, кто его ведёт и на чём обычно спотыкаются. Здесь перечня нет намеренно. Страница собирается из `src/data/templates.ts`, и вторая копия списка разъехалась бы с первой.

## Как пользоваться

Открой файл шаблона на GitHub, скопируй сырой текст кнопкой «Copy raw file» и положи к себе. Дальше правь под свой сервис: названия секций и состав полей в шаблоне не обязательны, это отправная точка.

Сначала прочитай лист, на который шаблон ссылается. Шаблон показывает форму документа, а лист объясняет, какое решение за этим документом стоит. Заполненная форма без решения ничего не даёт.

## Как устроен шаблон

- В шапке два списка: «Когда применять» и «Когда не применять».
- Привязок к компаниям, внутренних кодов процессов и чужих названий команд в шаблоне нет.
- Отдельной лицензии у шаблона нет: он распространяется под [Apache 2.0](../LICENSE), как весь репозиторий.

## Как добавить шаблон

Один шаблон — один PR из трёх правок:

1. Файл `templates/<name>.md`. Имя латиницей через дефис.
2. Запись в `src/data/templates.ts`: `id` совпадает с именем файла без расширения, в `leaves` перечислены id листьев, где документ разобран.
3. Ссылка на шаблон в тексте каждого листа из `leaves`, адресом `https://github.com/jtprogru/The-Way-of-SRE/blob/main/templates/<name>.md`.

`make data-check` не пропустит файл без записи, запись без файла и связь с листом, записанную только с одной стороны. Общий порядок работы с репозиторием — в [CONTRIBUTING.md](../CONTRIBUTING.md).
