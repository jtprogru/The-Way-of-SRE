# Стиль-чек листьев

Механическая часть чеклиста готовности листа из [`inventory/style-guide.md`](../../inventory/style-guide.md) §5. Проверяет то, что проверяется однозначно, и молчит там, где нужен человек.

```bash
make style                                  # все листья: сводка и ранжирование
make style LEAF=src/content/docs/leaves/culture/runbooks.md
make style-ci                               # только детерминированные правила, для CI

python3 tools/style/scan_leaf.py --all --full   # полный отчёт по каждому листу
python3 tools/style/scan_leaf.py --all --json   # машиночитаемо
```

## Что проверяется

| Правило | Что ловит |
| --- | --- |
| §1, §5 | голос автора и его распределение по секциям |
| §2.2, §2.3 | наличие явного мнения и границы применимости |
| §3.1 | доля шаблона «утверждение / антипаттерн / правильно» в Best practices |
| §3.2 | первый абзац, повторяющий frontmatter `description` |
| §3.4 | лимит безличных «должен / следует» |
| §3.5 | падежные гибриды через дефис |
| §3.6 | «Инструменты» без позиции автора |
| §3.7 | кальки и переводческий канцелярит |
| §3.8 | длина и многострочность `description` |
| §4.3 | доля источников с личной оценкой |
| ритм | разброс длин фраз и списочность прозаических секций |

Уровни в отчёте: `!` — нарушение контракта, правится; `~` — наблюдение, решает человек.

Лексические правила считаются по всему тексту, включая буллеты (голос живёт и в оценке источника), но без заголовков — иначе шаблонное «Что должен уметь» само себя штрафует по §3.4. Ритм считается только по прозе прозаических секций: «Что должен уметь», «Материалы» и «Связанные листья» списочны по контракту шаблона и в метрику не входят.

Whitelist гибридов собран из [`inventory/terminology.md`](../../inventory/terminology.md), раздела «Что разрешено»: аббревиатуры, имена собственные (`Telegram-нотификации`, `k8s-кластер`) и устоявшиеся сложения (`shell-скрипты`, `stateful-сервис`, `blameless-постмортем`) нарушением не считаются.

## Чего скрипт не умеет

§3.9 — выдуманные источники и числа — проверяется только открыванием ссылок. §2.1 — пример из практики от синтетического регексом не отличить. Скрипт говорит «маркера нет», а не «текст плохой», и `--ci` поэтому блокирует только по §3.1–§3.8.

## Пороги

`baseline.json` — не выдуманные значения, а перцентили по корпусу блога [jtprog.ru](https://jtprog.ru): 121 пост длиннее 200 слов за 2013–2026. Тревога срабатывает там, где текст выбивается из собственной нормы автора, а не из чужого представления о ней.

По листьям калибровать нельзя: они писались с моделью, и норма, снятая с них, узаконит ровно тот ровный ритм, от которого чек и лечит.

Пересчитать, когда в блоге накопятся посты:

```bash
python3 ~/.claude/skills/content-humanizer/scripts/calibrate.py <каталог-с-постами> --write
```

и скопировать получившийся `baseline.json` сюда.

## Происхождение файлов

`rutext.py`, `scan_rhythm.py` и `baseline.json` — из скилла `content-humanizer` коллекции [bear-skills](https://github.com/jtprogru/bear-skills), MIT, © 2026 Mikhail Savin. Скопированы, чтобы чек работал у любого, кто склонировал репозиторий, без установки коллекции. `scan_leaf.py` написан для этого проекта и апстрима не имеет.

Переключить на установленную версию модулей ритма, не трогая копии:

```bash
HUMANIZER_SCRIPTS=~/.claude/skills/content-humanizer/scripts make style
```
