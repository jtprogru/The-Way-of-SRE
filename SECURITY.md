# Политика безопасности

The Way of SRE — статический сайт на GitHub Pages. У него нет бэкенда, форм, учётных записей и пользовательских данных, поэтому поверхность атаки небольшая. Но она есть: сборка, зависимости и то, что попадает в опубликованный HTML.

## Что считается уязвимостью

- Код, который исполняется в браузере читателя без ведома автора: XSS через компоненты или контент, подмена скриптов на страницах сайта.
- Проблемы в CI: workflow, через который PR из форка получает доступ к секретам, праву записи в репозиторий или деплою.
- Уязвимая зависимость, которая реально достижима в сборке или на сайте, а не просто лежит в `bun.lock`.
- Способ опубликовать на сайте то, что не прошло через `main`.

## Что уязвимостью не считается

- Фактические ошибки, битые ссылки и устаревшие данные в листьях. Для них есть обычный issue по шаблону «Фактическая ошибка».
- Содержимое сторонних сайтов из разделов «Материалы». Если ссылка ведёт на скомпрометированный или сменивший владельца ресурс, открой обычный issue, такую ссылку уберём.
- Инфраструктура GitHub и GitHub Pages, включая TLS и заголовки ответа вроде CSP или `X-Frame-Options`: GitHub Pages не даёт их настраивать. Уязвимости самого GitHub — в [его программу](https://bounty.github.com/).
- Отчёты автоматических сканеров без демонстрации, как проблему эксплуатировать.

## Как сообщить

Приватно через GitHub: вкладка **Security → Report a vulnerability** или сразу [форма нового advisory](https://github.com/jtprogru/The-Way-of-SRE/security/advisories/new). Не открывай публичный issue и не пиши об уязвимости в чат.

В отчёт стоит положить: что и где уязвимо, шаги воспроизведения, какое влияние ты видишь.

## Что будет дальше

Мейнтейнеры занимаются проектом в свободное время. Получение отчёта подтвердим в течение 14 дней, дальнейшее обсуждение идёт в том же advisory. Исправление выходит обычным PR, после деплоя advisory публикуется, автор отчёта указывается в нём, если не против. Денежного вознаграждения нет.

## Поддерживаемые версии

Версий и релизов у проекта нет. Поддерживается только текущее состояние `main` и развёрнутый из него сайт.

## In English

Please report vulnerabilities privately via [GitHub private vulnerability reporting](https://github.com/jtprogru/The-Way-of-SRE/security/advisories/new), not through public issues or the Telegram chat. In scope: the published site, the CI workflows and reachable dependencies. Out of scope: factual errors in content, third-party sites linked from the leaves, GitHub Pages infrastructure and response headers, and unverified scanner output. Expect an acknowledgement within 14 days. There is no bug bounty.
